# مدیریت نشانی‌های مشتری

## مدل داده

نشانی‌ها در جدول `customer_addresses` و با ارتباط مستقیم به کاربر نگهداری می‌شوند. هر نشانی شامل عنوان، نام تحویل‌گیرنده، شماره تماس، کد کشور، استان/ایالت، شهر، دو خط نشانی، کد پستی و وضعیت پیش‌فرض است.

شماره تماس به قالب یک کشور خاص محدود نشده است. کد کشور دوحرفی و بزرگ‌نویسی‌شده مطابق قالب ISO 3166-1 alpha-2 است؛ اعتبارسنجی فعلی قالب را بررسی می‌کند و عضویت کد در فهرست رسمی را استعلام نمی‌کند.

هر کاربر می‌تواند نشانی‌های متعدد داشته باشد، اما فقط یک نشانی پیش‌فرض خواهد داشت. اولین نشانی به‌صورت خودکار پیش‌فرض می‌شود. تغییر نشانی پیش‌فرض و حذف نشانی پیش‌فرض در transaction و با قفل ردیف کاربر انجام می‌شوند؛ در صورت حذف نشانی پیش‌فرض، نشانی بعدی به‌صورت خودکار جایگزین می‌شود.

## API

تمام مسیرها به نشست احراز هویت‌شده Sanctum نیاز دارند و فقط نشانی‌های مالک حساب را برمی‌گردانند:

| متد    | مسیر                             | کاربرد                        |
| ------ | -------------------------------- | ----------------------------- |
| GET    | `/api/v1/me/addresses`           | فهرست نشانی‌های کاربر          |
| POST   | `/api/v1/me/addresses`           | ثبت نشانی                     |
| PATCH  | `/api/v1/me/addresses/{address}` | ویرایش نشانی یا انتخاب پیش‌فرض |
| DELETE | `/api/v1/me/addresses/{address}` | حذف نشانی                     |

دسترسی به نشانی متعلق به کاربر دیگر با پاسخ 404 رد می‌شود تا وجود شناسه‌های دیگران افشا نشود.

## رابط کاربری

صفحه مدیریت نشانی در مسیر `/settings/addresses` و از منوی تنظیمات حساب قابل دسترسی است. کاربر می‌تواند نشانی جدید بسازد، نشانی‌های خود را ویرایش یا حذف کند و نشانی پیش‌فرض را تغییر دهد.

## محدودیت فعلی

نشانی‌ها برای آماده‌سازی ارسال کالاهای فیزیکی ذخیره می‌شوند؛ هنوز سفارش، هزینه ارسال، انتخاب نشانی در checkout یا اتصال به شرکت حمل‌ونقل پیاده‌سازی نشده است.
