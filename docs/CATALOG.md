# قرارداد API کاتالوگ

این سند قرارداد دسته‌بندی‌ها و محصولات را ثبت می‌کند. قیمت، موجودی، گونه‌ها و جزئیات فروش تا زمان تعیین تصمیم‌های محصولی در محدوده فعلی نیستند.

## دسته‌بندی‌ها

هر دسته‌بندی دارای نام، شناسه یکتای URL، توضیحات اختیاری، والد اختیاری، ترتیب نمایش و وضعیت فعال/غیرفعال است. ساختار درختی با parent_id نگهداری می‌شود؛ پاسخ فهرست به‌صورت مجموعه تخت است تا کلاینت بتواند درخت را بدون محدودیت عمق بسازد.

### مسیرهای عمومی

| متد | مسیر                      | توضیح                        |
| --- | ------------------------- | ---------------------------- |
| GET | /api/v1/categories        | فهرست دسته‌بندی‌های فعال       |
| GET | /api/v1/categories/{slug} | جزئیات دسته‌بندی فعال با slug |

دسته‌بندی غیرفعال در API عمومی نمایش داده نمی‌شود و درخواست جزئیات آن پاسخ 404 می‌گیرد.

### مسیرهای مدیریتی

تمام مسیرهای مدیریتی به نشست احراز هویت‌شده Sanctum و مجوز access-admin نیاز دارند. صفحه مدیریت دسته‌بندی‌ها در /admin/categories قرار دارد.

| متد    | مسیر                          | توضیح                            |
| ------ | ----------------------------- | -------------------------------- |
| GET    | /api/v1/admin/categories      | فهرست صفحه‌بندی‌شده همه دسته‌بندی‌ها |
| POST   | /api/v1/admin/categories      | ایجاد دسته‌بندی                   |
| PATCH  | /api/v1/admin/categories/{id} | ویرایش دسته‌بندی                  |
| DELETE | /api/v1/admin/categories/{id} | حذف دسته‌بندی بدون زیردسته        |

### فیلدهای ورودی دسته‌بندی

- name: الزامی، رشته حداکثر 160 کاراکتر
- slug: الزامی هنگام ایجاد، یکتا و ASCII alpha-dash، حداکثر 180 کاراکتر
- description: اختیاری، حداکثر 10000 کاراکتر
- parent_id: اختیاری، شناسه دسته‌بندی والد موجود؛ چرخه و انتخاب خود دسته به‌عنوان والد مجاز نیست
- sort_order: اختیاری، عدد صحیح نامنفی
- is_active: اختیاری، مقدار boolean

حذف دسته‌بندی دارای زیردسته با پاسخ 409 رد می‌شود. ابتدا باید زیردسته‌ها منتقل یا حذف شوند. در صورت حذف یک دسته‌بندی بدون زیردسته، رکورد حذف می‌شود.

## محصولات

محصول در این مرحله یک موجودیت مستقل با نام، slug، توضیحات، ترتیب نمایش و وضعیت فعال/پیش‌نویس است. هر محصول می‌تواند به چند دسته‌بندی متصل شود و هر دسته‌بندی نیز می‌تواند چند محصول داشته باشد. ارتباط از طریق جدول واسط category_product نگهداری می‌شود.

محصول جدید به‌صورت پیش‌نویس (غیرفعال) ساخته می‌شود و فقط پس از فعال‌سازی مدیر در API عمومی نمایش داده می‌شود. محصولات عمومی صفحه‌بندی‌شده‌اند و فقط دسته‌بندی‌های فعال خود را در پاسخ نشان می‌دهند. پارامتر اختیاری category در فهرست محصولات، slug یک دسته‌بندی فعال را می‌گیرد و محصولات فعال متصل به همان دسته را برمی‌گرداند. جستجو در نام و توضیحات، مرتب‌سازی و صفحه‌بندی نیز برای ویترین عمومی فراهم است. صفحه مدیریت در /admin/products قرار دارد.

ویترین عمومی از صفحه اصلی /، صفحه دسته‌بندی /categories/{slug} و صفحه جزئیات محصول /products/{slug} تشکیل شده است. این صفحات با یک Layout مستقل از پنل مدیریت نمایش داده می‌شوند و داده‌ها را از API عمومی دریافت می‌کنند.

### مسیرهای عمومی

| متد | مسیر                             | توضیح                                   |
| --- | -------------------------------- | --------------------------------------- |
| GET | /api/v1/products                 | فهرست صفحه‌بندی‌شده محصولات فعال           |
| GET | /api/v1/products?category={slug} | فیلتر محصولات فعال بر اساس دسته‌بندی فعال |
| GET | /api/v1/products/{slug}          | جزئیات محصول فعال                       |

### پارامترهای فهرست عمومی محصولات

| پارامتر | نوع | پیش‌فرض | محدودیت و رفتار |
| --- | --- | --- | --- |
| category | string | — | slug دسته‌بندی فعال؛ فقط محصولات متصل به آن دسته |
| q | string | — | جستجوی عبارت در نام و توضیحات؛ حداکثر ۱۲۰ کاراکتر |
| sort | string | featured | یکی از featured، newest، name_asc یا name_desc |
| per_page | integer | 12 | تعداد در هر صفحه، از ۱ تا ۴۸ |
| page | integer | 1 | شماره صفحه؛ مطابق صفحه‌بندی استاندارد Laravel |

مرتب‌سازی featured ابتدا sort_order و سپس نام، newest بر اساس زمان ایجاد نزولی، و گزینه‌های name_asc و name_desc بر اساس نام انجام می‌شوند. پارامترهای فیلتر در لینک‌های صفحه‌بندی حفظ می‌شوند. ورودی نامعتبر برای sort یا per_page و سایر پارامترهای اعتبارسنجی‌شده پاسخ 422 می‌گیرد.

### مسیرهای مدیریتی

| متد    | مسیر                        | توضیح                            |
| ------ | --------------------------- | -------------------------------- |
| GET    | /api/v1/admin/products      | فهرست صفحه‌بندی‌شده همه محصولات     |
| POST   | /api/v1/admin/products      | ایجاد محصول                      |
| PATCH  | /api/v1/admin/products/{id} | ویرایش محصول و ارتباط دسته‌بندی‌ها |
| DELETE | /api/v1/admin/products/{id} | حذف محصول                        |

### فیلدهای ورودی محصول

- name: الزامی، رشته حداکثر 160 کاراکتر
- slug: الزامی هنگام ایجاد، یکتا و ASCII alpha-dash، حداکثر 180 کاراکتر
- description: اختیاری، حداکثر 10000 کاراکتر
- sort_order: اختیاری، عدد صحیح نامنفی
- is_active: اختیاری، مقدار boolean؛ پیش‌فرض false
- category_ids: آرایه اختیاری از شناسه دسته‌بندی‌های موجود و غیرتکراری؛ ارسال آرایه خالی ارتباط‌های قبلی را حذف می‌کند

### رفتار ارتباط دسته‌بندی‌ها

- محصول می‌تواند بدون دسته‌بندی ذخیره شود.
- دسته‌بندی نامعتبر یا شناسه تکراری با خطای اعتبارسنجی 422 رد می‌شود.
- هنگام ویرایش، اگر category_ids ارسال نشود ارتباط‌ها حفظ می‌شوند؛ اگر آرایه ارسال شود، ارتباط‌ها با همان آرایه جایگزین می‌شوند.
- حذف دسته‌بندی، ارتباط‌های واسط آن را به‌واسطه کلید خارجی حذف می‌کند؛ خود محصول حذف نمی‌شود.

## پاسخ‌ها و خطاها

پاسخ منابع در کلید data قرار می‌گیرند. فهرست‌ها ساختار صفحه‌بندی Laravel را برمی‌گردانند. خطاهای اعتبارسنجی 422، عدم ورود 401، نداشتن مجوز 403 و نبود منبع عمومی 404 هستند.

## موارد خارج از محدوده فعلی

- قیمت، واحد پول، تخفیف و مالیات
- موجودی و انبار
- گونه‌ها و ویژگی‌های قابل انتخاب محصول مانند رنگ و اندازه
- تصاویر و رسانه‌های محصول
- SKU و بارکد
- نوع کالا (فیزیکی، دانلودی یا خدمات)
- چندفروشندگی و Marketplace
- SEO و ترجمه چندزبانه
- آرشیو نرم و بازیابی محصول یا دسته‌بندی
